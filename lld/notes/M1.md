# M1 - The TypeScript Survival Kit (7 sessions)

We build toward one artifact: a typed Task Manager mini-app (10-12 small files, no patterns yet). Every concept lands as code in that app. Python analogue called out each time so it hooks to what you already know.

## Session 1 - Types, inference, signatures, unions, literal types

**Recall (M0):** why `strict: true` is on. `strictNullChecks` is the one that most changes how you write code - a value that can be missing must be checked before use.

**Concept:** TypeScript's job is to make illegal states unrepresentable *at compile time*. Three tools today:

1. Inference - you usually don't annotate locals. `const n = 5` is already typed `number`. Annotate at boundaries (function params/returns, public APIs).
2. Union types - a value that can be one of several things: `string | number`.
3. Literal types + unions of literals - the closest thing to Python's enums for cheap: `"todo" | "in_progress" | "done"`.

Python analogue: `Literal["todo", "in_progress", "done"]` from `typing`, and `Union[str, int]`.

```ts
type Status = "todo" | "in_progress" | "done";

function labelFor(status: Status): string {
  switch (status) {
    case "todo": return "Not started";
    case "in_progress": return "Working on it";
    case "done": return "Finished";
  }
}
```

No default in that switch: with a union-typed input, TS knows the cases are exhaustive and infers the return is always a string. Add a 4th status later and every such switch errors until you handle it - that's the compiler earning its keep.

**Function signatures** - annotate params and return type at module boundaries:

```ts
function add(a: number, b: number): number { return a + b; }
```

Inside small closures/callbacks, inference is fine.

**Task Manager step 1.** Create `lld/src/task.ts`:

```ts
export type Status = "todo" | "in_progress" | "done";

export interface Task {
  id: number;
  title: string;
  status: Status;
}
```

And `lld/tests/task.test.ts` with a couple of assertions around a small pure function you write, e.g. `moveTask(task, status): Task` (returns a NEW task object - do not mutate).

```ts
it("moves a task without mutating the original", () => {
  const t: Task = { id: 1, title: "Write tests", status: "todo" };
  const t2 = moveTask(t, "done");
  expect(t2.status).toBe("done");
  expect(t.status).toBe("todo"); // original untouched
});
```

Hint for immutability: `{ ...t, status }` (spread makes a shallow copy).

**Definition of done:** `npx vitest run` green, `npx tsc --noEmit` clean, no `any` anywhere.
