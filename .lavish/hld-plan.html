How every session runs

5-10 min

Recall

Rebuild yesterday's diagram of the current system from memory. Paper first, then compare against your notes.

10 min

Fundamental

One building block (classic or AI) plus the week's math corner, always answering: what problem it solves, when it is the wrong tool. Five bullets in hld/notes.md.

35-45 min

Design work

One section of the 7-part treatment for the current system. Days 1-6: one section each. Day 7: redraw everything from memory.

Mastery gate (your rule): if a fundamental or a design section feels shaky, we stay on it with more examples and a from-memory redraw until it is cold. No moving on.

The template you learn to draw in 10 minutes

Every system is a variation of this shape. You will draw it from memory until it is automatic, then adapt it per problem.

The dashed line is write-back from workers. Once this shape is reflex, every system is "which parts change?".

The 7-part treatment

  1. Requirements: functional and non-functional, and what is explicitly out of scope
  2. Estimation: back-of-envelope QPS, storage, bandwidth - before any component choices
  3. API design: the 3-5 endpoints that matter, with pagination and versioning
  4. Data model: entities, access patterns, SQL vs NoSQL justified by the pattern
  5. High-level diagram: clients, services, caches, queues, stores - drawn from the template
  6. Deep dive: the two hardest bottlenecks, in real numbers
  7. Trade-offs: failure modes, and what you would change at 10x scale

Thread 2 - AI systems (agentic and RAG)

Trending in interviews and in everyday work. Same 7-part treatment, with AI-specific deep dives: quality evals, cost per token, time-to-first-token, and the failure modes unique to probabilistic systems. Fridays.

Design 1

RAG knowledge assistant

Ingestion and chunking, embeddings, vector store, hybrid search, re-ranking, citations, evals. Deep dives: recall versus latency, freshness, cost.

Design 2

Agentic workflow engine

Tool calling, planning loops, state and memory, retries, human-in-the-loop, sandboxing, budget limits. Deep dives: determinism, tool idempotency, blast radius.

Design 3

LLM inference serving

Continuous batching, KV cache, quantization, GPU pools, autoscaling, token streaming. Deep dives: throughput versus latency, tail latencies, cost per million tokens.

Design 4

Assistant with memory

Session memory, long-term vector memory, personalization, guardrails, privacy. Deep dives: memory relevance, poisoning, deletion semantics.

Fundamentals covered along the way: embeddings and vector search (ANN, HNSW), chunking strategies, evaluation harnesses, prompt and semantic caching, streaming protocols, cost control.

Thread 3 - under the hood + the math corner

The differentiator you asked for: knowing how the elegant systems you rely on actually work, and the math that explains why designs hold at scale. This is the part that changes how you think, not just what you know.

Under the hood: one real system every 2 weeks

  • Postgres: MVCC, WAL, heap storage, B-tree indexes, the query planner
  • CouchDB: document model, append-only B-trees, the replication protocol
  • Redis: event loop, data structures, persistence modes, cluster topology
  • Kafka: log segments, partitions, consumer groups, exactly-once semantics
  • CDN edge (Cloudflare-style): anycast, edge caching, request routing, cache keys
  • Load balancers (L4 vs L7): connection handling, algorithms, health checks, draining

Format: a study day, then a one-page write-up with an internals diagram in hld/, then explain it from memory next session.

Math corner: one topic per week

  1. Little's Law and utilization
  2. Percentiles and tail latency
  3. Capacity estimation models
  4. Quorum math (R + W > N), Raft basics
  5. Consistent hashing math and virtual nodes
  6. Probabilistic structures: Bloom, count-min, HyperLogLog error bounds
  7. Caching math: hit rate, working set, LRU vs LFU
  8. Power of two choices in load balancing
  9. Rate limiting math: token bucket, leaky bucket
  10. Queueing networks and backpressure (M/M/1 basics)
  11. CAP and PACELC formalized
  12. Vector search math: ANN trade-offs (recall vs latency vs memory)

The real-world thread

Production note per system

Every system ends with three lines on how the big shops actually run it, and how the same concerns appear in the systems you work on: queues where you have seen timeouts, caches where you have seen staleness.

Weekly application task

Once a week: pick one concept and map it to your actual work. Where does your team cache? What would sharding your main table look like? Five lines in hld/notes.md.
