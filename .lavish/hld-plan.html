The template you learn to draw in 10 minutes

Every system is a variation of this shape. You will draw it from memory until it is automatic, then adapt it per problem.

The dashed line is write-back from workers. Once this shape is reflex, every system is "which parts change?".

The 7-part treatment

  1. Requirements: functional and non-functional, and what is explicitly out of scope
  2. Estimation: back-of-envelope QPS, storage, bandwidth - before any component choices
  3. API design: the 3-5 endpoints that matter, with pagination and versioning
  4. Data model: entities, access patterns, SQL vs NoSQL justified by the pattern
  5. High-level diagram: clients, services, caches, queues, stores - drawn from the template
  6. Deep dive: the two hardest bottlenecks, in real numbers
  7. Trade-offs: failure modes, and what you would change at 10x scale

The 12 weeks

Phase 1

October: vocabulary + first system

  • Vertical vs horizontal scaling; latency vs throughput
  • Back-of-envelope estimation (QPS, storage, bandwidth)
  • Load balancing; CDN and DNS
  • Caching strategies, eviction, invalidation
  • SQL vs NoSQL; replication; sharding
  • CAP and consistency models; idempotency and retries
  • API design: REST, pagination, versioning

System 1: URL shortener, the October checkpoint, written end to end.

Checkpoint: URL shortener fully written + diagram redrawn from memory

Phase 2

November: building blocks + systems

  • Message queues (Kafka-style concepts); pub/sub
  • Event-driven design; saga for distributed transactions
  • Consistent hashing; distributed cache; rate limiting at scale
  • Search basics: inverted index; observability basics

Systems 2-6, one per week: chat, news feed, typeahead, distributed cache, rate limiter.

Checkpoint: 4 systems written, HLD mock 1 done

Phase 3

December: hard systems + polish

  • Ride sharing: geo-indexing, matching, surge
  • Video streaming: upload pipeline, transcoding, delivery
  • Ticket booking: concurrency, locking, no overselling
  • Payments: idempotency, ledger, consistency
  • Notification service; web crawler

Systems 7-12, plus scaling deep dives and multi-region trade-offs on the earlier designs.

Checkpoint: all 12 done, HLD mocks 2 and 3, deep-dive redraws from memory

The real-world thread

Production note per system

Every system ends with three lines on how the big shops actually run it, and how the same concerns appear in the systems you work on: queues where you have seen timeouts, caches where you have seen staleness.

Weekly application task

Once a week: pick one concept and map it to your actual work. Where does your team cache? What would sharding your main table look like? Five lines in hld/notes.md.
